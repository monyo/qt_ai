# 質化分析方法論與現行系統差距分析

日期：2026-09-14

對照文件：`docs/qualitative-investment-research-methodology.md`

## 1. 結論先行

現行系統已經具備「候選觸發、基本資料粗篩、LLM 文字摘要、報告輸出」的雛形，但距離經驗型投資經理人的質化研究仍有本質落差：

> 現行系統主要是在量化候選上加一層 AI 解釋；方法論要求的是從商業本質、證據、預期差與反證出發，形成可驗證的投資論點。

最大的缺口不是模型名稱或分數，而是：

1. 沒有真正的研究問題分類與 thesis。
2. 沒有證據來源、日期、口徑與可信度。
3. 沒有反向論證與市場預期拆解。
4. 沒有自由現金流、資本報酬、負債與盈利品質的系統檢查。
5. 催化劑與風險沒有形成可觀察的傳導鏈。
6. LLM 目前主要讀取程式傳入的摘要數字，不是讀取完整研究資料。
7. 目前的分數和 verdict 容易把「資料漂亮」誤當成「應該買」。

## 2. 能力對照矩陣

| 方法論能力 | 現行狀態 | 判定 |

| 標的類型分類 | 有 Momentum、ROTATE、Early Value、Value With Confirmation | 部分具備；分類仍偏策略標籤，不是研究問題 |
| 一句話商業模式 | 沒有結構化欄位 | 缺口 |
| 收入引擎拆解 | 只有 revenue_growth | 缺口 |
| 護城河與競爭位置 | LLM 依一般背景撰寫，沒有公司證據欄位 | 缺口 |
| 財務品質 | 主要有 PE、PEG、營收成長、目標價 | 嚴重缺口 |
| 市場預期反推 | 沒有隱含 EPS、利潤率、成長預期或估值情境 | 缺口 |

## 3. 現行流程實際在做什麼

### 候選層

`collect_qualitative_candidates()` 會從盤前 actions 建立候選，並補入 `VALUE_ADD`。這部分已符合「不要只分析動能矛盾」的要求。

### 資料層

目前傳給質化產生器的資料主要是：

- current price
- momentum
- RSI
- alpha 1Y/3Y
- trend state
- forward PE
- PEG
- analyst target mean
- target upside
- revenue growth
- sector
- action reason

這是一組選股與技術摘要，不是完整的公司研究資料。

### 分析層

目前由一次 LLM request 對全部候選生成：

- valuation
- momentum_state
- timing
- score
- verdict
- catalyst
- risk
- invalidation
- recommendation
- quant_action_override
- final_recommendation

問題在於輸出欄位雖然增加了，但輸入沒有提供足夠證據支持這些結論。輸出格式變完整，不代表分析本身變深。

### 決策層

目前系統可以在報告中顯示 `upgrade`、`confirm`、`confirm_but_wait` 等欄位，但沒有真正把質化判斷回寫成新的交易規則或部位大小。它目前是「決策回饋資訊」，不是完整的決策融合引擎。

## 4. 最重要的落差

### 4.1 把低估條件當成低估證明

目前價值池使用：

- Forward PE < 25
- PEG < 1.5
- 分析師目標價上檔 > 15%
- 營收成長 ≥ 0
- 3Y alpha 不低於 -20%

這些可以作為粗篩，但不能證明低估：

- PE 低可能是盈利即將下滑
- PEG 低可能是成長估計過度樂觀
- 分析師目標價是共識資料，不是內在價值
- 正營收成長可能伴隨負自由現金流
- 3Y alpha 只是相對價格表現，不是商業品質

需要新增「為什麼市場錯」以及「什麼證據可證明市場錯」兩個核心欄位。

### 4.2 沒有獲利品質

目前沒有系統化檢查：

- 毛利率趨勢
- 營業利益率
- 自由現金流／淨利
- 應收帳款與存貨增速
- 資本支出
- 股份稀釋
- ROIC
- 淨負債與利息負擔

因此可能把「營收正在成長但股東沒有得到現金」誤判成高品質成長。

### 4.3 沒有市場預期差

投資報酬不是來自公司「不錯」，而是來自實際結果超過價格中已反映的預期。

現行分析沒有回答：

- 市場目前預期幾年成長
- EPS 需要到哪裡才能支持現價
- 利潤率要改善多少
- 哪些預期已經反映在股價
- 哪一個變數若超預期會觸發重估

### 4.4 催化劑沒有傳導鏈

現行文字常會出現「AI、資料中心、能源轉型、廣告市場成長」等方向，但缺少：

> 事件 → 部門收入 → 毛利／營業利益 → 自由現金流 → 市場重新定價

沒有傳導鏈時，催化劑只是主題，不是投資論點。

### 4.5 風險沒有可執行的觀察指標

例如「競爭加劇」、「宏觀經濟風險」、「政策不確定」都太泛。

應轉成：

- 風險事件
- 對收入、利潤或現金流的影響
- 下一季要觀察的指標
- 何時觸發降級或退出

### 4.6 一次 LLM request 造成過度概括

目前一次把全部標的送給模型，容易出現：

- 每檔都得到類似的催化劑
- 每檔都得到泛用風險
- 低 PE + 正成長直接變成強力推薦
- 模型無法針對不同公司類型切換研究框架
- 沒有反方回合，結論容易受初始資料方向影響

這不是單純換模型能解決的問題，必須先改善輸入資料與研究流程。

## 5. 優先補缺順序

### P0：先修正研究可信度

1. 將 Gemini 依賴改為與 Hermes/GPT 相容的分析執行方式；模型不是方法論核心，但目前架構與使用者預期不一致。
2. 修正文件中「Claude」與實際模型不一致的描述。
3. 增加資料來源、發布日期、財報期間與 GAAP/adjusted 標記。
4. 若 PE、EPS、營收指引互相矛盾，強制輸出 `data_quality_warning`，禁止直接 `strong_buy`。
5. 不再把分析師目標價上檔當成主要安全邊際。

### P1：建立真正的研究資料包

每檔至少準備：

- 公司一句話商業模式
- 收入分部與成長驅動
- 毛利率、營業利益率、自由現金流
- ROIC 或資本報酬代理指標
- 淨負債、利息、股份數變化
- 管理層最新指引
- 主要客戶與集中度
- 競爭者與替代方案
- 最近重大事件
- 來源、日期與口徑

### P2：由單輪摘要改成研究流程

建議最小流程：

1. Fact extraction：只抽事實，不下投資結論
2. Thesis construction：建立多頭 thesis 與估值隱含假設
3. Bear review：專門攻擊 thesis
4. Decision synthesis：整合後才產生 action

### P3：建立可驗證決策

每檔輸出：

- `research_archetype`
- `core_thesis`
- `why_mispriced`
- `supporting_evidence`
- `counter_case`
- `catalysts` with transmission chain
- `risks` with warning signals
- `invalidation_conditions`
- `bear/base/bull` scenarios
- `action`
- `position_guidance`
- `next_review_triggers`

### P4：建立事後學習

不只記錄價位績效，還要回看：

- 原始 thesis 是否成立
- 哪一個證據判斷正確或錯誤
- 催化劑是否如期發生
- 是估值擴張還是獲利改善帶來報酬
- 是否過早買入或錯過確認
- 模型何種標的最容易過度樂觀

## 6. 不應直接做的事

在上述缺口補上前，不應：

- 直接將 LLM 分數映射成部位大小
- 以目標價上檔排序後宣稱安全邊際
- 以「upgrade」自動覆寫風控或交易動作
- 以單季營收成長推論長期商業品質
- 以正動能或負動能替代商業研究
- 以一段泛用風險文字當作 downside analysis

## 7. 建議的下一個最小切片

不要一次重寫整套系統。第一個切片建議只做「研究資料包＋雙階段分析」：

1. 對每個 VALUE_ADD 產生結構化 research packet。
2. 抽取至少五類證據：商業模式、成長驅動、財務品質、估值假設、主要風險。
3. 先產生一版多頭 thesis。
4. 再產生一版 bear review。
5. 最後輸出 `buy / watchlist / reject`，並保留支持與反對證據。

這個切片可以直接驗證：質化分析是否真的找到「被低估但尚未被動能反映」的公司，而不是只把低 PE 股票改寫成綠色推薦。

## 8. 核心判斷

現行系統的優勢是候選範圍與交易脈絡已經整理得不錯，尤其是價值池現在已經不再被動能預先截斷。

現行系統的核心弱點是：

> 它已經能夠完整地問「要分析哪些股票」，但還不能可靠地回答「為什麼這家公司在這個價格下值得投資」。

下一階段應優先補證據、預期差、反證和財務品質，而不是繼續增加 verdict、分數或更多文字欄位。
